Build a Self-Hosted Linux
Network Storage Server with Mornye

Author: NavyaXdev • Scope: Hardware, Linux & Docker • Read Time: 11 min

Commercial network-attached storage (NAS) appliances from vendors such as Synology, QNAP, or Asustor have become increasingly expensive, restrictive, and dependent on proprietary cloud services. Many modern commercial NAS platforms lock users into proprietary disk formats, require registered vendor accounts for remote access, and bundle heavy, closed-source operating systems that consume hardware resources.

Building your own self-hosted private cloud storage server on Linux offers complete data sovereignty, superior performance, lower total cost of ownership, and ultimate flexibility. By combining standard Linux distributions (Debian, Ubuntu, or Kali), Docker containerization, and Mornye Network Storage, you can turn any repurposed office desktop, mini PC (such as an Intel N100), or rackmount home server into an enterprise-grade private storage vault.

1. Hardware Selection: Finding the Right Balance

RECOMMENDED

Intel N100 Mini PC

Under 6W idle power consumption. 4 modern cores, 16 GB RAM, dual 2.5GbE LAN ports, and native NVMe/SATA slots for silent, low-power continuous operation.

BUDGET REUSE

Repurposed Desktop

Any older Intel Core i3/i5 (6th gen+) or AMD Ryzen desktop with multiple 3.5" SATA bays for high-capacity multi-terabyte arrays.

SBC CLUSTERS

Raspberry Pi 5 / 4

Pair Raspberry Pi 5 (4GB/8GB) with an NVMe PCIe hat or USB 3.0 enclosure for a compact, ultra-silent private cloud node.

STORAGE MEDIA

NAS-Rated Drives

CMR-based drives (WD Red Plus, Seagate IronWolf) for long-term vibration resistance, or NVMe SSDs for lightning-fast random I/O.

2. Storage Partitioning & Auto-Mount in `/etc/fstab`

Format your dedicated storage disk with POSIX-standard ext4:

bash — format-partition 
# Format dedicated storage partition with ext4
sudo mkfs.ext4 -L MornyeStorage /dev/sdb1

# Create mount directory
sudo mkdir -p /mnt/mornye_data

# Retrieve partition UUID
sudo blkid /dev/sdb1

Add the partition to /etc/fstab to guarantee auto-mounting on system boot:

bash — fstab-entry 
# Append to /etc/fstab:
UUID=your-uuid-here /mnt/mornye_data ext4 defaults,noatime 0 2

# Mount and verify
sudo mount -a
df -h /mnt/mornye_data

3. Hardening Permissions for Rootless Docker (UID 1000)

Ensure that the storage mount is owned by unprivileged UID 1000:

bash — chown-mount 
sudo chown -R 1000:1000 /mnt/mornye_data
sudo chmod 700 /mnt/mornye_data

4. Deploying Mornye & Linking Dedicated Storage

bash — deploy-and-link 
# 1. Clone repository
git clone https://github.com/navyaXdev/Mornye-Network-Storage.git ~/mornye
cd ~/mornye
chmod +x setup.sh mornye.sh
./mornye.sh install

# 2. Stop service and symlink dedicated partition to storage
./mornye.sh stop
rm -rf storage
ln -s /mnt/mornye_data storage
./mornye.sh start

5. Zero-Trust Cloudflare Ingress Setup

Eliminate router port forwarding completely:

bash — tunnel-setup 
# Launch guided tunnel provisioning (auto-configures mornye.yourdomain.com)
./mornye.sh tunnel setup

6. Ongoing Operations & Automated Hot Backups

bash — ops-commands 
# 1. 11-Category system health audit
./mornye.sh doctor

# 2. Real-time CPU, RAM & container telemetry
./mornye.sh monitor

# 3. Create zero-downtime hot online SQLite snapshot
./mornye.sh backup create
