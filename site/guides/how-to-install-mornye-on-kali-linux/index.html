How to Install Mornye Network Storage on Kali Linux Step-by-Step

Author: NavyaXdev • Target: Kali Linux Rolling (x86_64, Kernel 7.1.5+) • Read Time: 9 min

Kali Linux is globally recognized as the premiere distribution for security research, digital forensics, and penetration testing. However, security researchers and lab engineers frequently require a secure, self-hosted file vault and media repository on their Kali workstations or headless servers. Setting up cloud storage on Kali has historically been frustrating due to strict upstream Debian package pinning, bleeding-edge kernels (such as Kernel 7.1.5+), and port conflicts with penetration testing listeners (e.g., Metasploit, Burp Suite, or custom HTTP bridges).

In this comprehensive tutorial, you will learn how to deploy Mornye Network Storage on Kali Linux Rolling. We will cover environment preparation, resolving permission issues with unprivileged Docker containers (UID: 1000), configuring port coexistence on port 8001, setting up Argon2id WebDAV authentication, and enabling encrypted Cloudflare Tunnels.

Prerequisites & Environment Verification

Before beginning, ensure your Kali Linux installation meets the following baseline requirements:

  • Distribution: Kali Linux Rolling (2024.x – 2026.x).
  • Architecture: x86_64 (amd64) or aarch64 (e.g. Raspberry Pi Kali build).
  • User Privileges: Standard user with sudo privileges or root.
  • Available Disk Space: At least 2.5 GB free disk space.

Verify your kernel and architecture in the Kali terminal:

uname -srm
# Example output: Linux 7.1.5+kali-amd64 x86_64

Step 1: Update APT Repositories & Install Prerequisites

Mornye includes an automated APT installer (installers/apt.sh), but updating your local package indices ensures seamless Docker Engine installation:

sudo apt update && sudo apt install -y curl git ca-certificates gnupg lsb-release

Step 2: Clone the Mornye Network Storage Repository

Clone the official GitHub repository created by NavyaXdev and enter the project directory:

git clone https://github.com/navyaXdev/Mornye-Network-Storage.git
cd Mornye-Network-Storage
chmod +x setup.sh mornye.sh

Step 3: Launch the 6-Stage Automated Setup Wizard

Launch the interactive Mornye setup engine:

./mornye.sh install

The installer will automatically execute the following stages:

  1. System Audit: Detects Kali Linux via /etc/os-release and routes dependency installation through installers/apt.sh.
  2. Docker Verification: Checks for Docker Engine and the Docker Compose v2 plugin. If missing, it installs the official Kali docker packages (docker.io, docker-compose-plugin).
  3. Storage Volume Provisioning: Creates the host directories (database/, storage/, logs/, backups/) and hardens ownership to UID 1000:1000 with chmod 700.
  4. WebDAV Authentication: Prompts you to configure WebDAV credentials. You can choose to generate a cryptographically secure random password or specify your own custom secret.
  5. Container Build: Compiles the hardened rootless mornye-webdav image.
  6. Ingress Selection: Choose between Local LAN mode (http://127.0.0.1:8001/dav/), an ephemeral Quick Tunnel, or a permanent Cloudflare Tunnel.

Understanding Kali Linux Port Coexistence (`8001:8000`)

A common pitfall on Kali Linux systems is port collision. Many security researchers run local web hooks, reverse shells, or legacy daemons that occupy TCP port 8000. Mornye prevents collisions by binding to host port 8001 while routing internally to port 8000 within the Docker bridge:

# Check port binding
./mornye.sh ports
# Output shows: 127.0.0.1:8001 -> container port 8000

This allows Mornye to run simultaneously alongside existing port 8000 processes with zero service termination or interference.

Troubleshooting: Resolving Docker `/data` Permission Denied

On Kali Linux systems where the repository was previously cloned or manipulated with sudo, host directories might mistakenly be owned by root:root (UID 0). Because Mornye strictly executes as unprivileged user mornye (UID 1000), this can cause:

[*] Mornye Container Bootstrapping...
mkdir: cannot create directory '/data': Permission denied

To resolve this instantly, use Mornye's automated self-healing diagnostic command:

./mornye.sh doctor --fix

The diagnostic engine will inspect the permissions, detect the UID mismatch, create a safety backup, and correctly execute:

sudo chown -R 1000:1000 ./database ./storage ./logs
sudo chmod 700 ./database ./storage ./logs

Step 4: End-to-End Service Verification

Verify that your Mornye installation is healthy and ready for file transfers:

# 1. Inspect complete system diagnostic
./mornye.sh doctor

# 2. Probe the WebDAV HTTP endpoint
./mornye.sh health

# 3. Test WebDAV Basic Authentication (Argon2id)
./mornye.sh webdav test

# 4. View real-time container dashboard
./mornye.sh dashboard

Step 5: Accessing Your Storage

You can now connect to your WebDAV storage:

  • From Kali Linux: Open Thunar or GNOME Files, press Ctrl+L, and enter: dav://127.0.0.1:8001/dav/
  • From Remote Clients (Windows/macOS/Mobile): Use your Cloudflare Tunnel URL: https://mornye.yourdomain.com/dav/
Kali Linux Deployment Complete!

Your Mornye Network Storage instance is fully operational with rootless container security, Argon2id encryption, and automated diagnostics.
