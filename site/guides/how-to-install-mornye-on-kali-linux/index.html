How to Install Mornye on
Kali Linux Step-by-Step

Author: NavyaXdev • Platform: Kali Linux Rolling (Kernel 7.1.5+) • Read Time: 9 min

Kali Linux is globally recognized as the premiere distribution for security research, digital forensics, and penetration testing. However, security researchers frequently require a secure, self-hosted file vault and media repository on their workstations or remote VPS instances. Setting up cloud storage on Kali has historically been frustrating due to strict upstream Debian package pinning, bleeding-edge kernels (such as Kernel 7.1.5+), and port conflicts with penetration testing listeners (such as Metasploit, Burp Suite, or custom HTTP bridges).

This tutorial demonstrates how to deploy Mornye Network Storage on Kali Linux Rolling with non-root Docker UID 1000, host port 8001 coexistence, and automated Cloudflare Tunnels.

Prerequisites & Environment Verification

DISTRIBUTION

Kali Linux Rolling (2024.x – 2026.x)

ARCHITECTURE

x86_64 (amd64) or ARM64

PRIVILEGES

Sudo or root shell access

STORAGE

At least 2.5 GB free disk space

Step 1: Update APT Repositories & Core Tools

bash — apt-update 
sudo apt update && sudo apt install -y curl git ca-certificates gnupg lsb-release

Step 2: Clone the Official Repository

bash — clone-repo 
git clone https://github.com/navyaXdev/Mornye-Network-Storage.git
cd Mornye-Network-Storage
chmod +x setup.sh mornye.sh

Step 3: Launch the 6-Stage Automated Setup Wizard

Launch the interactive setup wizard. The script automatically detects Kali Linux via /etc/os-release, installs Docker via native channels, provisions hardened directories, and configures authentication:

bash — mornye-install 
./mornye.sh install
KALI SPECIAL FEATURE

Protected Port Coexistence (8001:8000)

Security professionals running Kali frequently have local testing tools occupying port 8000 (such as local staging hooks, proxy listeners, or debug servers). Mornye maps host port 8001 to container port 8000, ensuring peaceful coexistence without port collisions:

bash — verify-ports 
# Check active port binding
./mornye.sh ports
# Output shows: 127.0.0.1:8001 -> container:8000
Self-Healing Fix for Docker Permission Denied:

If you previously ran commands with sudo, host directories might be owned by UID 0 (root). To realign permissions to unprivileged UID 1000 automatically:

./mornye.sh doctor --fix

The doctor creates a safety snapshot and runs chown -R 1000:1000 ./database ./storage ./logs safely.

Step 4: End-to-End Health Verification

bash — health-diagnostics 
# Run complete 11-category system diagnostic
./mornye.sh doctor

# Probe WebDAV daemon health
./mornye.sh health

# Test WebDAV authentication boundary
./mornye.sh webdav test
