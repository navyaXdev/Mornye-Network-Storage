How to Configure Cloudflare Tunnel Subdomains for Mornye Network Storage

Author: NavyaXdev • Network Ingress: Cloudflare Zero-Trust • Read Time: 9 min

Self-hosting storage on home or office servers traditionally presents severe networking hurdles. Most consumer and small-business ISPs place connections behind Carrier-Grade NAT (CGNAT), share dynamic IP addresses, and aggressively block inbound traffic on ports 80, 443, and 8080. Opening ports in home routers also introduces significant security risks by exposing the server's public IP to internet-wide botnets and port scanners.

Mornye Network Storage overcomes these obstacles by integrating Cloudflare Zero-Trust Tunnels directly into its setup lifecycle. When configuring your custom domain, Mornye automatically creates a dedicated subdomain (mornye.<root-domain>), configures edge TLS 1.3 encryption, and establishes an encrypted outbound tunnel directly to Cloudflare's edge network—requiring zero open router ports.

The Automated Subdomain Architecture

When you connect your domain through Mornye, you do not need to manually create DNS records or configure reverse proxy routing tables. The automated setup works as follows:

  1. Root Domain Input: You enter your root domain (e.g. example.com or mydomain.in).
  2. Automatic Subdomain Construction: Mornye constructs mornye.example.com.
  3. Cloudflare Authentication: Verifies that your domain exists in your Cloudflare account.
  4. DNS Record Management: Checks whether a DNS record for mornye.example.com already exists. If a conflict is found, it prompts for confirmation or update.
  5. Tunnel Configuration: Generates an ingress configuration routing all traffic for mornye.example.com to local loopback port http://127.0.0.1:8001.
  6. Edge SSL: Cloudflare automatically issues and manages free edge TLS certificates, terminating HTTPS at the edge before streaming over the QUIC tunnel.

Step-by-Step Configuration

Step 1: Authenticate Cloudflared CLI

If you have not already logged in to your Cloudflare account from your server, authenticate the cloudflared daemon:

cloudflared tunnel login

The CLI will output an authentication URL. Open this link in your browser, select your domain's zone, and authorize the tunnel. This securely downloads your cert.pem certificate to ~/.cloudflared/cert.pem.

Step 2: Launch Mornye's Guided Subdomain Wizard

Launch the automated tunnel provisioning tool:

./mornye.sh tunnel setup

When prompted:

  • Select Option 2: Use Your Own Domain (Permanent Tunnel).
  • Enter your root domain (e.g., example.com).
  • Mornye will automatically output: 
    [+] Configured dedicated subdomain: mornye.example.com
[+] Generating Cloudflare Tunnel: mornye-storage...
[+] Creating DNS CNAME record: mornye.example.com -> <tunnel-uuid>.cfargotunnel.com
[+] Routing traffic to local service: http://127.0.0.1:8001

Alternatively, you can bind your domain directly via the CLI in a single non-interactive command:

./mornye.sh tunnel domain add example.com

Step 3: Test WAN Connectivity & Security Boundary

Once setup completes, run Mornye's automated WAN probe:

./mornye.sh tunnel test

This command queries the public URL through Cloudflare and verifies:

  • DNS CNAME resolves to the active tunnel.
  • Edge SSL certificate is valid and enforces TLS 1.3.
  • Unauthenticated requests receive an HTTP 401 Unauthorized response.
  • Authenticated requests with valid Mornye credentials succeed with HTTP 200 OK or 207 Multi-Status.

Decoupling or Resetting a Domain

If you ever migrate to a new domain or wish to remove the tunnel, Mornye provides clean decommissioning commands:

# Check active tunnel and domain details
./mornye.sh tunnel status

# Remove dedicated subdomain route safely
./mornye.sh tunnel domain remove

# Reset all Cloudflare tunnel configuration files
./mornye.sh tunnel domain reset

Troubleshooting Cloudflare Ingress Issues

Error Code / Symptom Probable Cause Remediation Step
HTTP 502 Bad Gateway cloudflared is running, but Mornye WebDAV container on port 8001 is unreachable. Run ./mornye.sh doctor --fix to verify container health and port binding.
Error 1033 (Argo Tunnel Error) Cloudflare edge cannot locate the active tunnel daemon for this UUID. Restart the tunnel service with ./mornye.sh restart or verify cloudflared tunnel run.
Error 1016 (Origin DNS Error) The DNS CNAME record points to a deleted or non-existent tunnel UUID. Run ./mornye.sh tunnel domain reset and re-run ./mornye.sh tunnel setup.
HTTP 401 Unauthorized Expected behavior when accessing without credentials. Valid credentials must be passed via Basic Auth. Enter your configured Mornye WebDAV username and password in your client.

Conclusion

By automating dedicated subdomain provisioning (mornye.<root-domain>) and utilizing encrypted outbound QUIC tunnels, Mornye Network Storage delivers an enterprise-grade private cloud experience without compromising home network perimeter security.
