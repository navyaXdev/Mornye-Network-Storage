CONTAINER HARDENING

Hardened Architecture.
Rootless Docker Deployment.

Mornye Network Storage is engineered around the principle of least privilege. In contrast to legacy container images running as UID 0 (root), Mornye enforces strict non-root execution (UID 1000) with all Linux capabilities dropped.

Production Compose Specification (compose.yaml)

yaml — compose.yaml 
services:
  mornye-webdav:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: mornye-webdav
    restart: unless-stopped
    user: "1000:1000"
    security_opt:
      - no-new-privileges:true
    cap_drop:
      - ALL
    ports:
      - "127.0.0.1:${MORNYE_HOST_PORT:-8001}:8000"
    volumes:
      - ./database:/data
      - ./storage:/storage
      - ./logs:/logs
    environment:
      - MORNYE_PORT=8000
      - MORNYE_STORAGE_ROOT=/storage
      - MORNYE_DB_PATH=/data/mornye.db
    healthcheck:
      test: ["CMD", "curl", "-f", "http://127.0.0.1:8000/health"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 10s

Port 8001 Coexistence & Loopback Protection

Protected Coexistence

Host Port 8001 Shield

Mornye maps host port 8001 to container port 8000 by default. If your host is running Icecast relays, dev servers, or proxies on port 8000, Mornye coexists harmoniously without conflicts.

Network Isolation

Strict 127.0.0.1 Loopback

The container port binds exclusively to 127.0.0.1 instead of 0.0.0.0. Unauthenticated network sniffers or public interfaces cannot reach raw WebDAV sockets directly.

Volume Mounts & POSIX Permissions

Persistent directories on the host filesystem are mapped with strict permission boundaries:

Host Directory Container Mount Owner / Permissions Functional Scope
./database /data 1000:1000 (0700) SQLite mornye.db database, WAL journals, and virtual folder collections
./storage /storage 1000:1000 (0700) Encrypted physical file storage for documents, music, and streaming media
./logs /logs 1000:1000 (0700) Access logs, error telemetry, and daemon execution traces

Docker CLI Control Commands

bash — docker-commands 
# Start container stack in background
docker compose up -d

# Inspect running container and healthcheck state
docker compose ps

# Follow live WebDAV access & daemon logs
docker compose logs -f mornye-webdav

# Execute integrated health probe via Mornye CLI
./mornye.sh docker health
Self-Healing Permissions Repair

Encountering permission warnings when mounting volumes? Simply execute:

./mornye.sh doctor --fix

The self-healing diagnostic engine automatically creates a safety snapshot and realigns host directory permissions to match unprivileged UID 1000.
