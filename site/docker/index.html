Docker Deployment & Hardened Architecture

Engineered by NavyaXdev • Docker Compose v2 • Unprivileged UID: 1000

Mornye Network Storage is built strictly following the principle of least privilege. In contrast to many containerized NAS apps that run their inner processes as root (UID 0), Mornye enforces strict non-root operation with an unprivileged system user (mornye, UID/GID 1000) and dropped Linux kernel capabilities.

Production Compose Specification (`compose.yaml`)

Mornye utilizes a streamlined, hardened Docker Compose service configuration:

services:
  mornye-webdav:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: mornye-webdav
    restart: unless-stopped
    user: "1000:1000"
    security_opt:
      - no-new-privileges:true
    cap_drop:
      - ALL
    ports:
      - "127.0.0.1:${MORNYE_HOST_PORT:-8001}:8000"
    volumes:
      - ./database:/data
      - ./storage:/storage
      - ./logs:/logs
    environment:
      - MORNYE_PORT=8000
      - MORNYE_STORAGE_ROOT=/storage
      - MORNYE_DB_PATH=/data/mornye.db
    healthcheck:
      test: ["CMD", "curl", "-f", "http://127.0.0.1:8000/health"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 10s

Host Port Binding & Port Protection

Mornye maps host port 8001 to container port 8000 by default:

  • Protected Coexistence: If your host is running another service on port 8000 (such as a local API bridge, legacy server, or proxy), Mornye will not collide with it or terminate it.
  • Loopback Isolation: The port is bound explicitly to 127.0.0.1 (loopback) rather than 0.0.0.0 (public WAN). This prevents inadvertent exposure to local network scanners or unsecured Wi-Fi.

Volume Mounts & Permission Hardening

Mornye maps three primary directories from the host filesystem into the container:

Host Directory Container Path Owner / Permissions Description
./database /data 1000:1000 (0700) SQLite mornye.db database, WAL journals, and virtual folder indices
./storage /storage 1000:1000 (0700) Physical storage repository for uploaded files and audio media
./logs /logs 1000:1000 (0700) WebDAV access logs and daemon runtime logs

Quick Docker CLI Commands

Manage the container stack using standard Docker commands or the unified Mornye CLI:

# Start container in background
docker compose up -d

# Verify container status and healthcheck
docker compose ps

# View live container logs
docker compose logs -f mornye-webdav

# Execute diagnostic probe via Mornye CLI
./mornye.sh docker health
Self-Healing Permissions

If you encounter Permission Denied when mounting volumes, run:

./mornye.sh doctor --fix

The diagnostic engine will automatically adjust host directory ownership to match the container's unprivileged UID.
